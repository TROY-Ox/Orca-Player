# ORCA Player v0.9.0: Phase 9, library and extras

## What's new

- **Media library.** Movies and series built from your folders and from network shares marked "Show in library". File and folder names are read for title, year, S01E02, episode ranges and anime numbers. Online details come from TMDB with your own API key (TMDB attribution is shown), and online lookups can be turned off. Movies, Series and Collections tabs, watched and unwatched marks, sorting by any field, Fix match, manual editing and "This is a movie / an episode".
- **Network shares.** Saved connections for SMB 2/3, SFTP, FTP and FTPS, WebDAV and DLNA/UPnP (found on the local network). Passwords are stored encrypted. Files play with seeking, and can be copied to the device.
- **Audio-only mode.** Any video plays as audio with the screen off, with a music queue, shuffle, repeat, lock-screen and notification controls and the sleep timer.
- **File manager and private folder.** Multi-select in the Local tab with search, sort, rename, move, copy, delete and share (Android asks once per batch for files the app doesn't own). A private folder locked by fingerprint, face or PIN keeps videos encrypted in app storage and plays them without decrypting first, with Unhide and a clear warning that uninstalling deletes it.
- **Mini player and floating window.** The video docks above the navigation bar when you leave the player. System picture-in-picture is the default over other apps; an optional floating window (off by default) can be dragged and resized.
- **Picture filters.** Brightness, contrast, saturation, gamma, hue, sharpness, sharpening and upscaling shaders and deinterlacing, with presets and per-video settings. Filters switch off for HDR video.
- **Bluetooth audio delay.** Per-device audio delay that is remembered for each Bluetooth output.
- **Chromecast.** A Cast button in the player. Local files, private-folder files, shares and streams with headers go through a small token-protected server on the phone; SRT subtitles are converted to WebVTT. The phone becomes the remote: play, seek, subtitles, volume and next/previous. Files a Chromecast can't play are explained instead of failing silently, and effects are marked unavailable while casting.
- **libVLC engine.** Files Media3 can't open (for example WMV) can open in a second, simpler player. It can do this automatically (Settings › Sources) or from the error panel. The player says which features are missing in that mode.
- **Trakt.** Settings › Sources › Trakt. Enter your own Trakt API app's client ID and secret, then sign in with a device code (works on TV). Scrobbling for titles with IMDb or TMDB IDs (addon and extension titles and matched library items), watchlist import into My List and watched-history import into the library.

## How it was tested

- Devices and Android versions: not tested on a device yet. The cloud build environment cannot run an emulator, and the owner asked for one APK at the end of all phases.
- CI run: unit tests (new: file name parsing for the library, share URIs, WebDAV, DIDL and UPnP device descriptions; plus all earlier tests), lint for both flavors and the standard-flavor licence check.
- Manual checks from the phase's "done when" list (real SMB/SFTP/FTP/WebDAV/DLNA servers, a Chromecast, a Trakt account, HDR with filters): pending a device.

## Known issues

- Trakt progress sync is scrobble based (start, pause, stop); a full two-way progress sync is not done.
- DLNA discovery uses plain SSDP, so servers on other subnets must be added by address.
- The libVLC player has basic controls only: no Tools panel, equalizer, filters or casting.
- Chromecast tracks: subtitles are offered as WebVTT sidecars; switching the audio track while casting is not supported yet.

## Decisions made where the prompt was silent

- DLNA uses a small built-in SSDP and SOAP client, because jUPnP is EPL licensed and the standard build avoids weak-copyleft code where a small client will do.
- Share credentials never go into URIs: shares use app-private schemes that look up the encrypted connection when the file opens.
- Casting uses the Default Media Receiver, so no receiver app registration is needed.
- libVLC (LGPL-2.1-or-later) is in both builds and listed in Licences; it is loaded as a separate library, as the licence allows.
- Users bring their own TMDB key and Trakt app keys, since keys inside an app can be extracted.
