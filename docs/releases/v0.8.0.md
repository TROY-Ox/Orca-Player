# ORCA Player v0.8.0: Phase 8, CloudStream extensions (extended build only)

## What's new

- **Extended build only.** Everything in this phase lives in the extended build (GPL-3.0, sideload only). The standard build is unchanged and links none of it.
- **Repositories.** In Addons › CloudStream extensions, add a repository by its repo.json link or a `cloudstreamrepo://` link. ORCA reads every plugin list the repository names. Nothing is built in or suggested. A trust screen comes first every time: extensions are code that runs inside the app with its access, so add only repositories you trust.
- **Extensions.** Each one shows its icon, name, version, language, content types, size, status (not working, slow or beta), authors and description, with search and filters by language and type. Install, update, update all, turn off without uninstalling, and uninstall. Extensions that need a newer plugin API are marked incompatible, and files over 50 MB, with the wrong size or hash, or that aren't extension files are refused. Automatic updates are off by default and run only on Wi-Fi when the app starts.
- **Same screens as addons.** Every provider an extension registers becomes an entry in the Addon Manager, marked "Extension", with the same switch, order, per-profile and Kids settings and catalog editor (rename, reorder, Home or Discover, row style, featured area). Its main page sections are catalogs and Home rows, its search joins unified search, its titles open in the details screen with seasons and episodes, and its links go to the stream picker with quality, headers, referer, HLS and DASH, plus subtitles. Resume, My List, Continue Watching, automatic fallback and downloads (with the saving rule) work as for addons. IMDb IDs from extensions merge their titles with other sources. Filter chips Addons and Extensions were added to the list.
- **Isolation.** Extensions are loaded with a class loader from read-only files in app-private storage, inside a separate ":extensions" process. Requests have timeouts and are cancelled when you leave a screen. If an extension crashes or hangs, only that process stops; the app reports the error for that source and starts the process again on the next request. Updating, turning off or removing an extension restarts the process, because loaded code can't be unloaded.
- **Host API.** The extended build includes the CloudStream library module (recloudstream, v4.8.0, GPL-3.0) that extensions are compiled against, with the runtime libraries it is built with (NiceHttp and OkHttp, Jsoup, Jackson, Rhino, coroutines), and provides the Android `Plugin` base class extensions extend. Licences lists them.

## How it was tested

- Devices and Android versions: not tested on a device yet. The cloud build environment cannot run an emulator, and the owner asked for one APK at the end of all phases.
- CI run: unit tests (new: repo.json and plugins.json parsing, compatibility, repository link handling, relative URLs, safe file names and extension IDs; plus all earlier tests), lint for both flavors and the standard-flavor licence check. The extended build compiles against the CloudStream library.
- Manual checks from the phase's "done when" list (a test extension from a test repository, its rows, search, details, links and subtitles, and a crashing extension): pending a device and a test repository built from CloudStream's plugin template.

## Known issues

- Extensions that use parts of the CloudStream app that are not in its library module (its settings storage, video click actions, its own screens) fail to load and show why. An extension's own settings screen is not shown yet.
- Extensions that need their own resources (`requiresResources`) load without them.
- Pages that need a browser to solve JavaScript challenges depend on the library's own helpers; there is no WebView resolver screen yet.
- Torrent and magnet links from extensions are listed as unsupported, as for addons.
- Anime with subbed and dubbed lists shows both in one episode list, dubbed episodes marked "(Dub)".
- Casting requests are not passed to extensions until casting arrives in Phase 9.
- Very large answers from an extension (over about 1 MB) can't cross between processes and time out.

## Decisions made where the prompt was silent

- Extension providers are described to the rest of the app as addon-style entries, so every screen, setting and rule written for addons applies without a second code path.
- Short repository codes are not resolved, because that would ask a third-party service.
- The library is pinned to a release (4.8.0) rather than a moving snapshot, so builds are repeatable. JitPack is used only for `com.github.*` groups.
- When a repository lists a size or hash, the download must match it.

## Install

- Phone, tablet or TV: ORCA-Player-standard-v0.8.0.apk (unchanged by this phase)
- Extended build (sideload only): ORCA-Player-extended-v0.8.0.apk
- SHA256SUMS.txt lets you check the files were not changed.
